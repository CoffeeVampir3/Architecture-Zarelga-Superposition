DeepQwen3NextSeek · Engram + Attention-Residuals architecture

A ~1.04B-parameter language model where ~96% of parameters live in a hashed n-gram memory (the engram) and the additive residual stream is replaced by depth-wise softmax attention (AttnRes, arXiv:2603.15031). Every block reads from a shared pool of value sources — token identity, n-gram memory, and each earlier block's computation — instead of one accumulated sum.

≈1.04B params (≈22M backbone) d = 512 8 dense SwiGLU blocks vocab 16,384 ctx 8,192 packed varlen engram 2×4 heads · ~1.92M rows/head SWA 64/64/64/full · 128/128/128/full partial RoPE 16/64 dims

Global dataflow

Left spine: the computation path. Right rail: the depth-wise source pool. Before each block (and before the head), a mix site retrieves a per-token softmax combination of every source produced so far. Each block contributes only its delta (out − in) back to the pool — nothing accumulates implicitly.

Subsystems

Depth mix (AttnRes)

At site l, over sources v₀…v_{l-1+m}:

h_l = Σᵢ αᵢ·vᵢ,   αᵢ = softmaxᵢ( w_l · zRMSNorm(vᵢ) )
  • w_l: one 512-d pseudo-query per site, zero-init → every site starts as a uniform average (paper's stability requirement). 9 sites = 8 pre-block + 1 pre-head; 9,216 params total.
  • Keys RMS-normed in fp32 so no source wins by magnitude; values enter raw — a source's scale is carried by the source itself (e.g. the engram's value_proj).
  • Weights are per-token (input-dependent through keys), single head — both per the paper's ablations.
  • Site 0 is embedding-only (preserves the ablation-accepted "layer 0 sees only the embedding").
  • Replaces the engram's sigmoid context gate with softmax competition; mean α per (site, source) logged to Aim as attn_res/L*/….

Engram memory (~1.0B params)

  • Token ids → canonical ids (1,913 case/space variants merged) → suffix n-grams of order 2 and 3.
  • Each order hashed by 4 independent heads (multiply-XOR mod distinct primes ≥ 1.92M) → 8 tables, ~15.4M rows × 64d bf16.
  • Per token: gather 8 rows → × scalar importance weight (own hash) → per-head L2 cap ≤ 1 (shrink-only) → concat 512 → value_proj → Δmem.
  • Read once per step (weight-tied); under AttnRes it is one shared value source — no per-layer stream injections, no context gate.
  • Rows grow from zero under a sparse per-row RMSProp (GramReaperSparse) with an L2 ball cap; only touched rows (≤ 8/token) get gradients and updates, so step cost is flat in table size.
  • Corpus census: ~91M distinct bigrams / ~1.25B trigrams (10.2B tokens) → load ≈ 47 / 651 per head at this size.

Inside a block

u = h + Attn(zRMSNorm(h))
out = u + SwiGLU(zRMSNorm(u))
Δ = out − h  → source pool
  • Standard intra-block residuals (the paper's "Block AttnRes" intra-block accumulation, S=2); only the block's delta is exported.
  • MLP: SwiGLU 512 → 1280 → 512, all blocks dense (first_k_dense_replace=8; MoE machinery present but inactive in this config).
  • All norms are zero-centered RMSNorm (gain = 1 + w, w zero-init).

Gated attention

  • GQA: 8 query heads × 64d, 4 KV heads; QK-norm (zRMSNorm per head-dim).
  • Partial RoPE: 16 of 64 dims rotated (θ=100k), 48 NoPE dims; positions reset per packed segment.
  • Sliding windows: 64/64/64/full then 128/128/128/full — local layers interleaved with two global layers.
  • Attention sink: learnable per-head virtual key with zero value — a no-op escape hatch, exact gradients via the flash-attn LSE.
  • Output gate: per-head sigmoid from the pre-attention stream, then o_proj.
  • Flash-attention varlen over the packed stream (no padding, no cross-document attention).

Training pipeline

  • Data: pre-tokenized docs packed into one flat varlen stream; hard cap 196,608 tokens/batch (32 × 6,144; overflow truncated & logged) — bounds peak memory against rare all-long batches.
  • Loss: cut-cross-entropy (no logit materialization) + z-loss 1e-4 over valid tokens.
  • Optimizers: Muon-MD for 2-D weights, Adam for head/scalars/norm gains, GramReaperSparse (per-row RMSProp, fp32 scalar state) for embedding + engram tables; CUDA-graph captured.
  • Memory strategy: per-block torch.compile (one graph per block/mix/engram-read — a single whole-net graph let inductor overlap all blocks' recompute buffers, ~2.5× backward peak), checkpointed mix+block units, aux-loss-free MoE balancing (dormant), bf16 autocast over an fp32 stream.
  • At init: every mix is a uniform average (zero queries) — expect a distinct early loss-curve shape vs the additive baseline.
