Architecture Notes

Per-layer embedding and Engram-style neural architectures, restricted to the local curated corpus in good_papers/ and implementation references in good_references/. This document does not synthesize an unverified new architecture.

Boundary: every architecture statement below is tied to a cited local paper or reference snippet. Where a paper does not specify a detail, the note says not stated instead of filling it in.

Short Answer

Per-layer embedding

The important architectural choice is inside the FFN: most PLE/STEM descriptions attach the token-indexed table on the SwiGLU up-projection/value side, while preserving the hidden-state gate and down projection.

token-indexed inside FFN per layer

Engram

The important architectural choice is before the normal block compute at selected layers: Engram adds a residual memory branch to the hidden state, then the block continues through attention and MoE/FFN.

n-gram lookup context gate residual add

Related memory layers

The related papers mostly answer placement differently: replace FFNs, insert cross-attention memory layers, augment an attention layer, or route to expert FFNs. Those placements are not interchangeable.

PKM kNN cross-attn memory

Where Embeddings Go

This is the placement map the papers actually support. The rows distinguish the neural insertion point from the addressing method, because two methods can both use "embeddings" while attaching them to different places in the network.

Notation and block anatomy

The formulas in this section are not new assumptions; they are labels for parts of a standard gated FFN/SwiGLU sublayer so the paper snippets can be mapped to an actual network location.

Transformer decoder layer, simplified h_in -> self-attention sublayer -> add back to residual stream -> FFN / MLP sublayer -> add back to residual stream Standard gated FFN / SwiGLU hidden vector x -> gate branch: SiLU(Wg x) -> value branch: Wu x -> multiply those two FFN-width vectors element by element -> down branch: Wd maps the result back to model width

Symbol meanings

l: layer index. A subscript such as Wg_l means "the gate projection used by layer l."

i: token position in the sequence. A subscript such as x_i means "the hidden vector at position i."

x or x_l: the current token position's hidden vector entering layer l's FFN/MLP sublayer. It is not the raw token ID.

t or t_i: the current tokenizer ID at token position i. This is used for table lookup.

d_model: model hidden width. d_ff: FFN intermediate width after the up/gate projections and before the down projection.

Wg: FFN gate projection. SiLU(Wg x) decides which intermediate channels are active for this hidden-state context.

Wu: FFN up/value projection. Wu x is the normal context-derived candidate feature vector at FFN width.

Wd: FFN down projection. It maps the FFN-width vector back to model width for the residual stream.

*: elementwise multiply between same-width vectors, not matrix multiplication.

Per-layer embedding notation: U_l is the embedding table owned by layer l, with one row per token ID and width matching the FFN intermediate width in STEM. U_l[t] means "look up row t in layer l's table." In STEM and LongCat-style PLE, that looked-up row is placed where the standard FFN would normally use Wu x.
STEM / LongCat-style per-layer embedding placement hidden vector x -> gate branch: SiLU(Wg x) token id t -> layer-specific table U_l -> row U_l[t] SiLU(Wg x) * U_l[t] -> Wd maps back to model width -> result is added through the layer's normal residual path

Formula labels below are used only after these definitions; each row also spells out the tensor flow in prose.

Memorizing Transformer One attention layer near the top of the stack is replaced by a kNN-augmented attention layer. MoC Memory cross-attention layers are inserted at specified decoder layers. H' = H + CrossAttention(H, selected_memory_chapters) The paper specifies memory cross-attention at layers {2,6,10,14}. Its reported placement is before token mixing, not as an input embedding or Engram pre-attention residual branch in a standard Transformer block. FwPKM: "inserted before the token mixer"
Practical reading: if the design is per-layer embedding, look inside the FFN/SwiGLU path. If the design is Engram-style, look for a residual memory branch at selected blocks before normal block computation. If the design is PKM/Memory Layers/Hash Layers, look for FFN replacement. If the design is Memorizing Transformer/MoC, look in attention or cross-attention.

TN-gram Same selected Transformer-block interface as Engram. Replaces per-order/per-head hash tables with CP tensor factors shared across n-gram orders. Produces key/value through projection absorption, then follows Engram-style gate/conv/residual. TN-gram: "shared CP tensorized memory"
Memory Grafting Recipient Transformer grafting layers; same residual-memory write interface as Engram. Exact longest-match suffix lookup into frozen grafted memory; hash Engram fallback on misses. Memory Layers at Scale Replace one or more FFN layers; Memory+ uses three centered layers in reported setup. Hidden state query selects trainable key/value entries by top-k similarity. Weighted value sum, optionally with projection, gating, and SiLU nonlinearity. Memory Layers: "top-k most similar keys"
Product-Key Memory Replace selected FFN blocks or interleave memory between blocks. Query is split into sub-queries; product keys make exact nearest-key search efficient. Softmax over selected values; multi-head PKM sums independent memory-head outputs. PKM: "product key memory layer"
Hash Layers Replace one or more Transformer FFN sublayers with hash-routed expert FFNs. Original input token, not hidden state, is hashed to a fixed expert bucket. Selected expert FFN processes the hidden state; no learned router. Hash Layers: "fixed mapping to experts"
Memorizing Transformer One attention layer near top of stack. Approximate kNN over external cache of prior key/value pairs. Local attention and kNN-memory attention are combined by a learned per-head gate. Memorizing Transformer: "approximate k-nearest-neighbor search"
Mixture of Chapters Memory cross-attention layers inserted into decoder blocks. Sequence-level router selects top-k chapters from a learned latent-token bank. Token stream queries selected memory tokens through cross-attention, then residual add. MoC: "learned bank of latent tokens"
FwPKM Inserted before token mixer; standard PKM baseline replaces MLP. Product-key sparse retrieval with fast-weight key/value matrices updated online. Retrieved value interpolates with residual value path via gate, then output projection. FwPKM: "sparse fast-weight memory layer"

Per-Layer Embedding

1. PLE as modulation/additional block

STEM describes PLE as sharing FFN gate and down projections while adding token-level specificity. It also says PLE does not remove the original FFN in each decoder layer. Therefore, the source-backed architecture is not a standalone replacement for the whole FFN; it is a token-indexed sparse parametric memory path coupled to the FFN path.

Source boundary: the specific Google Gemma 3n PLE implementation is referenced by STEM and LongCat, but the local corpus does not contain an official Gemma technical spec for PLE. The notes here therefore rely on STEM/LongCat descriptions, not on a proprietary reverse engineering claim.

2. STEM as up-projection replacement

STEM makes the neural location explicit. For layer l, table U_l has shape V x d_ff: V rows for the vocabulary and d_ff columns to match the FFN intermediate width. The token row U_l[t] means "use token ID t to select one row from layer l's table."

At layer l, for one token position hidden vector x_l -> Wg_l gate projection -> SiLU activation -> context-dependent FFN-width gate vector token ID t -> lookup in table U_l -> FFN-width token row U_l[t] gate vector * token row -> Wd_l down projection -> model-width FFN output for the residual stream

So the architecture is not "put another embedding at the input." The lookup row is inserted inside the layer's FFN, in the same slot where the normal SwiGLU up/value branch would have produced Wu_l x_l.

The reason given in STEM is architectural: replacing the gate projection makes selection too context-independent, while replacing the up projection preserves hidden-state-dependent gating.

Evidence

STEM says PLE tables are in node-local CPU memory and prefetched, then proposes STEM as a stricter design with one per-layer table U_l.

Snippet: "layer-local embedding lookup"

LongCat uses the same FFN placement: its PLE notation E0_l(t_i) is a layer-specific token row, and PLNE changes that value source to an n-gram embedding output e_i_l.

Snippet: "Per-Layer N-gram Embedding"

Not stated in the local PLE descriptions: a universal rule for which layers must receive PLE, whether tables should always be shared across devices, or a final optimal PLE-vs-PLNE allocation.

Engram Block

DeepSeek Engram is an added residual branch at selected Transformer layers. It is not simply a bigger input embedding and it is not a learned router to experts. Its paper describes two phases: retrieval and fusion.

token ids -> tokenizer compression -> suffix n-grams for n = 2..N -> K hash heads per n-gram order -> per-order/per-head embedding rows -> concatenate retrieved rows into e_t -> k_t = W_K e_t, v_t = W_V e_t -> alpha_t = sigmoid(norm(h_t) dot norm(k_t) / sqrt(d)) -> gated value = alpha_t * v_t -> ShortConv(gated value) -> H_l = H_l + memory_output -> then standard Attention and MoE in the demo/reference block
Part Source-backed detail Do not infer
Tokenizer compression Raw token IDs are projected to canonical IDs before forming suffix n-grams. Do not assume every Engram variant keeps compression; the vision diagnostic explicitly does not.
N-gram orders Large-scale Engram uses [2,3]; reference ablations also use {2,3}. Do not assume higher orders are always better; TN-gram reports most gains by 5-gram in its setup, but that is a different parameterization.
Hash heads Engram-27B/40B table lists 8 heads, memory dim 1280, layers [2,15]. Do not assume 8 heads is universal; image Engram uses H=4.
Fusion Current hidden state is the query for a scalar gate over retrieved memory, followed by short depthwise causal convolution and residual add. Do not call this attention over the table; the table address is deterministic, and the gate controls write strength after retrieval.
mHC / multi-branch Paper shares sparse embedding table and value projection across branches, but uses distinct key projections for branch-specific gates. Do not apply mHC details to a single-stream backbone unless the backbone has those residual branches.
Placement DeepSeek reports layers 2 and 15 in the large model; ablation says layer 2 is best for single insertion, and layers 2 and 6 improve over one module in a 12-layer setup. Do not infer all layers should have Engram. The source says "applied only to specific layers".

Variant What changes What stays Engram-like Evidence
TN-gram Independent hash tables are replaced by CP tensor factors shared across n-gram orders. Lower-order n-grams are derived from the largest-order tensor using order-absorption vectors. Suffix n-gram extraction, selected Transformer blocks, key/value projections, hidden-state gate, depthwise causal conv, residual add. TN-gram: "same Engram context-aware gating"
Memory Grafting Frequent n-gram values are frozen hidden states from an offline grafting model; runtime uses exact longest-match lookup before falling back to hash Engram. Selected memory is projected to key/value, gated against recipient hidden state, passed through ShortConv, and added to the residual stream. Memory Grafting: "hash-based Engram fallback"
Vision Engram diagnostic Uses 2D spatial n-gram hashing over image-token grids, no tokenizer compression, and placements at layers {0,6,12,18} in the reported AR image model. Still uses hash-keyed memory, gated fusion, and residual side path. Image diagnostic: "gated architectural side-pathway"
Important caveat: the AR image paper is negative for a strict retrieval interpretation. It says the module is better described as "not as a content-addressed retriever" in that setting. That does not refute the LLM Engram architecture, but it does mean architecture-level lookup should not be equated with verified semantic retrieval without task-specific probes.

Related Designs

These papers are relevant because they specify alternate ways to insert sparse memory into a neural network. They are not the same architecture as Engram or PLE.

Design Architecture Why it is not Engram/PLE
Hash Embeddings Multiple hash functions select component vectors; learned importance weights combine them. It is an embedding compression/composition method, not a Transformer residual memory branch. Snippet from Hash Embeddings: "weighted sum"
spaCy multi-hash embeddings Production NLP embedding stack uses multiple hashes into vector tables for compact lexical feature embeddings. It backs the multi-hash primitive, but not per-layer Transformer memory. Snippet from spaCy report: "hashed multiple times"
Probabilistic Hash Embeddings Hash embedding rows are probabilistic variables with Bayesian online posterior updates for changing categorical vocabularies. It is a plug-in embedding module for online categorical features, not an LLM per-layer memory branch. Snippet from PHE: "hash embeddings as random variables"
Memory+ / Memory Layers at Scale Trainable key/value memory replaces FFN layers. Memory+ adds projection, gating, and SiLU. Addressing is hidden-state top-k over learned keys, not token-ID n-gram hashing.
PKM Query network produces query; product-key search selects values; multi-head PKM uses independent query networks and shared values. It usually replaces FFN blocks, whereas Engram is an added n-gram memory branch.
MoC Sequence-level router picks chapters of a learned latent-token memory bank, then cross-attention reads selected chapters. It is routed cross-attention over memory tokens, not deterministic n-gram lookup.
Memorizing Transformer A near-top attention layer augments local attention with kNN attention over a non-differentiable external cache. It stores prior activations per document; Engram stores trainable or frozen n-gram-addressed embeddings.
Hash Layers Original token is hashed to a fixed expert FFN bucket; multi-hash layers split FFN parameters into hashed segments. It routes computation to expert FFNs; Engram retrieves memory rows and gates a residual value.
FwPKM Fast-weight product-key memory retrieves sparse slots and updates key/value rows by chunk-level local gradient objectives during training and inference. It is online episodic memory, not static n-gram conditional memory.

Deployment Consequences

The CXL paper is not a new neural block. It is evidence that Engram's deterministic address path changes where memory can live.

Consequence Source-backed detail Architecture relevance
Prefetchability Engram indices depend on token IDs, so retrieval can start before hidden states at the target layer exist. Supports placing massive tables outside GPU HBM if latency can be hidden.
Sparse payload The CXL paper's case study reports "5 KB of data per token per layer". Bandwidth can be modest, but early-layer latency windows can be tight.
System architecture CXL pool stores Engram parameters centrally and workers fetch rows during forward pass. This changes serving infrastructure, not the mathematical Engram block.
